## Resumen

Tres hallazgos, ninguno crítico. El más concreto es un botón de recargar con un área táctil de
24dp, la mitad del mínimo accesible. Los otros dos son deuda de consistencia: siete textos de UI
fuera de `strings.xml` y la tarjeta de consejo de presupuesto pintada con colores propios en vez
de tokens del theme.

Vale aclarar algo que el barrido automático marca mal: los ocho colores hardcodeados de esta
pantalla **no** rompen el modo oscuro. Hay un comentario explícito en el código mostrando que se
pensó el caso y se resolvió a propósito. El problema real es otro y más chico.

## Hallazgos

### 1. Botón de recargar con área táctil de 24dp

**Severidad**: alta
**Dónde**: `ExpensesScreen.kt:710-719` — el `IconButton` de refrescar el consejo de presupuesto

```kotlin
IconButton(
    onClick = onRefresh,
    modifier = Modifier.size(24.dp)   // ← fuerza el botón a 24dp
) {
    Icon(..., modifier = Modifier.size(16.dp))
}
```

**Qué pasa**: `IconButton` trae 48dp por defecto justamente para cumplir el mínimo táctil. Acá
se lo pisa a 24dp, la mitad. A cualquiera le cuesta acertarle; para alguien con temblor o
dificultad motriz fina es directamente inutilizable. Es el único `IconButton` de la pantalla con
el tamaño pisado — los otros cuatro (182, 187, 409, 419) usan el default y están bien.

**Arreglo**: sacar el `Modifier.size(24.dp)` del `IconButton` y dejar el ícono chico si se
quiere el look compacto. El área táctil queda en 48dp y visualmente casi no cambia.

```kotlin
IconButton(onClick = onRefresh) {
    Icon(..., modifier = Modifier.size(16.dp))
}
```

### 2. Siete textos de UI fuera de `strings.xml`

**Severidad**: media
**Dónde**: `ExpensesScreen.kt` líneas 672-675, 699, 716, 766, 789

| Línea | Texto |
|---|---|
| 672-675 | `"Saludable"`, `"Advertencia"`, `"Crítico"`, `"Desconocido"` (etiquetas de estado) |
| 699 | `contentDescription = "IA"` |
| 716 | `contentDescription = "Recargar"` |
| 766 | `"Día ${advice.daysElapsed} de ${advice.totalDays}"` |
| 789 | `"No se pudo cargar el consejo de presupuesto."` |

**Qué pasa**: el repo usa `strings.xml` en serio — 436 strings y 477 `stringResource`. Estos
siete son la excepción, no la regla. Hoy el costo es que el texto vive en dos lugares y nadie
sabe cuál es la fuente de verdad; el día que se traduzca la app, quedan en español.

Los dos `contentDescription` son los más molestos: son lo que lee TalkBack en voz alta, así que
son texto de usuario aunque no se vean.

**Arreglo**: moverlos a `strings.xml`. El de la línea 766 necesita placeholders posicionales
(`Día %1$d de %2$d`) para que el orden se pueda cambiar al traducir.

### 3. Tarjeta de consejo de presupuesto con colores propios

**Severidad**: media
**Dónde**: `ExpensesScreen.kt:659-670`

```kotlin
val containerColor = when (advice.status) {
    "on_track" -> Color(0xFFE8F5E9) // Soft Green
    "warning"  -> Color(0xFFFFF3E0) // Soft Orange
    "critical" -> Color(0xFFFFEBEE) // Soft Red
    else       -> Color(0xFFF5F5F5)
}
val contentColor = when (advice.status) { /* verdes/naranjas/rojos oscuros */ }
```

**Qué pasa**: acá hay que ser precisa. El par contenedor/contenido es **auto-consistente**:
fondo pastel claro con texto oscuro encima, y todo lo que va adentro usa `contentColor`
explícitamente. El comentario de las líneas 728-730 lo dice con todas las letras — se usó
`contentColor` en vez de `onSurface` justamente porque `onSurface` en modo oscuro es blanco y
quedaba ilegible. **El texto se lee bien en los dos temas.**

Lo que sí pasa es que la tarjeta no se adapta: en modo oscuro queda un rectángulo pastel claro
en una pantalla oscura. No está roto, desentona. Y como los colores no salen del theme, cualquier
cambio de paleta futuro se olvida de esta pantalla.

**Arreglo**: agregar tokens de estado a `Color.kt` y al `ColorScheme` (con variante clara y
oscura), y consumirlos acá. Ya existen `SuccessGreen`, `WarningAmber` y `ErrorRed` en `Color.kt`,
pero les faltan los pares `*Container` / `on*` para este uso. El hallazgo es "faltan tokens de
estado en el sistema de diseño", no "reemplazá el literal por otro literal".

**No lo arreglé** porque toca la tarjeta de presupuesto, que es exactamente donde está trabajando
el otro agente. Coordinar antes de tocar.

## Sin hallazgos

Cosas que revisé y están bien:

- **`contentDescription = null` (líneas 432, 443)**: correctos. Son íconos decorativos en items
  de `DropdownMenu` que ya tienen texto visible al lado. Ponerles descripción haría que TalkBack
  lea todo dos veces. El barrido los marca; leídos en contexto, no son hallazgo.
- **Áreas táctiles del resto**: los `IconButton` de las líneas 182, 187, 409 y 419 usan el
  tamaño por defecto (48dp).
- **Estados de carga, éxito y error**: la tarjeta de consejo contempla los tres
  (`BudgetAdviceState.Loading` / `Success` / `Error`), incluso con acción de reintento. Es más
  de lo que suele haber.
- **Componentes compartidos**: usa `formatMoney` de `common/MoneyFormat.kt` en vez de formatear
  a mano. No reimplementa nada de `common/`.
- **Tipografía**: todo sale de `MaterialTheme.typography`. No hay tamaños sueltos.
